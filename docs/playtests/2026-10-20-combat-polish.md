# Combined build: combat readability and camera clearance

This pass starts at `codex/game-integration` 508207a, replays the camera-only eddce32 change, and preserves the integration branch's feathered/folded wings, momentum flight, chain combat and sculpted demon asset. Work is isolated on `codex/combat-polish` under Merge Monitor assignment 6a01ccec-2295-4c5c-819c-4a7d875d9913; Claude cross-review is required before integration. Counter and wing follow-up work remains separate.

The target cue now identifies the actual struck demon until contact, instead of independently selecting a different enemy during the dive. Afterwards it previews the next eligible target or explicit queued target. A directional arrow within screen margins replaces a vanishing offscreen cue; labels distinguish striking, chain, queued and turn. It remains a pointer-transparent visual cue; the existing Chain button and C issue attacks. No React state updates or second camera writer were added.

Pillar clearance no longer drops the boom by coarse 20% steps. It refines the obstruction boundary, retracts immediately, holds briefly, and bounds outward release. The held position is checked again after a turn: a longer clear view takes priority if the old shorter radius would hide the new target. The normal camera collision sphere still runs first. Ordinary flight, FOV and strike mechanics retain their existing implementation.

Baseline combined-build encounters passed on desktop 1440×900, landscape touch 852×393 and portrait touch 393×852. After the existing 180 ms settling window, both projected anchors were in frame in all sampled baseline frames (98 / 79 / 102 samples respectively). This is head/target-center visibility, not a guarantee about the whole animated character, all geometry, or every possible chain.

Verification covers real three-hit chains and banishments in all three layouts, locked cue identity, bounded edge positions, pilot override, Brake release, flight momentum, touch glide, camera switching, orientation, pause, context loss and automated accessibility. The unit suite passes all 2,472 tests in 207 files. TypeScript, the production build, vote-route build and the unchanged 629 KB landing budget pass. The first behavior run passed all 25 cases; a final run exercises the completed clearance and cue refinements. A real Rapier pillar regression checks that a stationary view varies by less than 8 cm over the sampled hover, clears the sightline, releases at a bounded speed, and rechecks a held radius when the target changes sides.

Physical iPhone Safari, motion comfort and subjective enjoyment have not been tested on a device. The combined build still has a one-role enemy encounter. Captures show remaining HUD clutter and the legacy “Blaster sound is off” hint; these are outside this camera assignment and remain follow-up work.
